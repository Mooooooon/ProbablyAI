## 自动中英文切换

界面、设置标签、操作记录、错误提示、容器名称、客人查询与工具说明自动跟随**游戏内**的语言设置：中文使用中文，英文使用英文，其他语言回退英文。语言切换时会关闭已打开的 Mod 面板，重新打开后显示新语言；不会翻译或改写你输入的文本。

未编辑的内置默认提示词会随游戏语言切换：中文称呼“主人”，英文称呼“Master”，保留女仆设定并默认禁止颜文字和 emoji。已保存的中文或英文默认模板也会适配；自定义提示词完整保留。提示词语言变化后，下次发送会清理旧上下文。

## 当前功能

- 以用户提供的 DeepSeek 拟人形象为参考，生成 1024 × 1536 透明 PNG 全身立绘。当前为双手在身前自然下垂交叠的女仆姿势，带像素画风；使用 Point 采样保留像素边缘。
- 进入当铺后显示于界面左侧；保留完整宽高比，按游戏画布缩放。
- 鼠标悬停人物时显示手形光标和高亮，点击打开聊天框；透明背景仍可穿透点击。
- 主菜单、离店、暂停菜单、设置和射击模式中隐藏。
- 待机时立绘以脚底为基准轻微改变高度，模拟呼吸；脚部位置保持不变，只有身体向上轻轻舒展。默认幅度 6 像素、周期 3.6 秒（1080p 基准），可单独关闭或调整。
- F6：本次运行中显示 / 隐藏立绘。F7：打开 / 关闭连接配置窗口（输入框聚焦时也能关闭）。
- 客人进店时自动小声提醒：符合通缉令特征或改造体时，立即在聊天或屏幕上的小卡片里提醒，不必等到聊天。提醒只触发一次，不向客人透露，也不会自动举报或攻击；治安官、检查员等当值安保访客不会被误报。可在 Mods 设置的“客人提醒”中关闭。
- 查看道具时可读取通用耐久：当前值 / 上限、剩余百分比、是否耗尽，以及未鉴定显示值或已鉴定值的来源。支持过滤器及其他采用原生耐久系统的道具；F7 手动操作的物品详情也显示。使用或过滤后可重新查询，按“耗尽停止”的指令判断。
- 可按自然语言指令倒水、倒酒、倒掉液体和在水龙头接水，使用游戏原生的物品对物品操作，并由游戏判定所有权、锁定、容量、过滤器和水龙头解锁状态。
- 可像玩家一样对非战斗物品执行原生物品对物品和使用 / 激活操作：试纸、扫描仪、书籍、医疗、手术、动物、食物、机器和工具等都可以尝试；武器可用于屠宰动物，但不会对顾客、敌人使用或代操作霰弹枪射击模式，交易和改存档仍不开放。
- 工具调用上限可调：F7 的“工具调用上限”可设置每条消息处理轮数（1–1000，默认 16）和工具调用次数（1–10000，默认 48）。复杂重复任务可同时调高，保存后下次发送生效，重启后保留；执行中仍可停止。调高可能增加耗时和 API 费用。
- 聊天上下文上限可调：F7 可设置发送给模型的对话轮次（1–50）和历史 token 估算上限（1,000–200,000），超限时从最旧的完整轮次开始省略；完整聊天记录按存档槽保存在本机，重启后恢复，手动清空聊天才删除。
- 主菜单 → Mods → 深空AI：可能是DeepSeek 的齿轮中，可保存高度、左右位置、底部位置、透明度、呼吸动画及快捷键设置。

## 点击立绘聊天

点击人物本身即可打开聊天框；重复点击会聚焦已经打开的窗口。透明背景不响应点击。

聊天面板会记住拖动后的位置，关闭再打开或重启游戏后恢复。位置单独保存在本机 ModData 的 `chat-window.local.json`，不包含对话或密钥，也不进入发布包。

- 输入自然语言，按 **Enter** 或点击 **发送**。**Shift+Enter** 换行。
- 输入框下方有 **快捷发言** 按钮：**按照客户需求挑选商品** 会结合当前客人的需求、预算和货品挑好并直接摆到柜台上；**帮我鉴定对方带来的东西** 会逐件检查窗口里客人带来的物品。点击后直接发送，输入框中尚未发送的草稿会保留。
- 默认提示词要求先完成主人的任务，完成后直接结束，不在结尾反问、追问、请求确认或主动提议下一步；只有缺少必要信息、确实无法安全执行时才先问一个简短问题。
- 例如：“帮我把食物放到柜台上”。助手会按游戏 `FOOD` 类型查找自有物品栏及其子容器中的食品，再用一次批量移动把多堆商品一起摆到柜台上。面包、罐头等名称不含“食物”的物品也能匹配。
- 聊天共用 F7 中保存的服务地址、密钥和模型；需要调整时可点聊天框内的 **连接设置**。F7 配置页也提供 **打开聊天** 入口。
- 支持多轮对话和跟进指令。完整聊天记录按存档槽保存在本机，重启或重新载入存档后会恢复，只有手动“清空聊天”才会删除。F7 中可把发送给模型的对话轮次上限设为 1–50，把历史 token 上限设为 1,000–200,000（估算）；超限时从最旧的完整轮次开始省略，不会删除聊天记录或拆断工具调用与结果配对，只改这两个上限也不会清空聊天。关闭窗口后重新打开仍可继续。发送给模型的历史会省略旧查询数据，并把已执行操作标记为历史，保留聊天窗口里的原记录。每条消息自动重新读取当前客人与柜台内容、数量和所有权，避免把上一单的货品当作仍待售；刷新失败时不沿用旧数据。更换服务地址、密钥、模型或提示词后，下次发送会清空旧上下文及对应的本机记录。F7 的“测试对话”和“手动操作”页的助手指令不共用这段聊天上下文，每次独立处理。
- 工具执行结果会显示在聊天中；可以 **停止**。已完成的操作保留，未执行的后续调用不会继续。模型的内部思考内容不会显示在聊天里。

聊天使用统一工具注册表。现有容器工具已经注册，未来经同一接口注册的工具会自动提供给模型和聊天窗口，无需修改聊天发送逻辑。扩展方法见 [docs/hands-api.md](docs/hands-api.md)。

## 客人、预算与需求

点击立绘后，可以直接问：

- “当前客人叫什么，来买东西还是卖东西？”
- “这位客人还剩多少预算，想买什么，不收什么？”
- “物品栏里有哪些他愿意买、预算也够的物品？先告诉我。”
- “这位客人的易货 / 采购 / 枪械委托有什么要求？”

助手通过 `get_current_customer` 读取当前到访对象、实时剩余购买预算、购买标签及指定物品、拒收规则、多样性要求和当前显示的对话。易货返回每条交换条件；采购返回需求说明及报酬；枪械委托区分必需条件与加分条件。不同客人拥有独立的到访 ID，没有客人或尚未到达时不返回上一位信息。未来对话分支和选项不会被执行或提前读取。

`BUY` 表示客人买店主的货，`SELL` 表示客人向店主卖货。预算是客人的实时剩余购买额度，与店主现金、初始额度和委托报酬分开。未启用预算时不填数值，不能理解为零或无限现金。

通缉与改造体提醒改在客人进店时由本地代码触发，不再依赖模型回复：聊天窗口打开时提醒直接写入聊天记录，关闭时显示一张会自动消失的小卡片。`get_current_customer` 仍返回 `wanted`（`is_wanted`、`stealth`、`quiet_reminder`）和 `aug`（`is_aug`、`quiet_reminder`），供主人点名询问时回答；提醒只触发一次，不向客人透露通缉、赏金或真名，也不会自动举报、报警或改变交易。已经举报或通缉令已结案的客人不会重复提醒。所有当值安保/检查员访客（`isSecurity` 及 `securityOfficer*`、`securityInspector`、`patrolOfficer`、`morningSecLeader` 等）会被显式排除，不会因为制服或执法对话被误报为通缉犯/改造体；有独立剧情的腐败警官（如 `officerLun*`）不在排除范围内。该提醒不进入模型上下文，所以模型不会照抄或反复刷屏。

助手可使用 `check_customer_item` 按游戏原生购买规则核对真实物品，包括嵌套容器里的物品；旧客人 ID 会被拒绝。柜台顶层物品直接读取原生实时报价；自有物品上柜台前会预估多种多样、当前价格事件、零售加价及已知客人效果，按属性、市场、最终谈价乘区计算，并返回价格明细。预算比较使用已含加成的报价，模型不应重复叠加百分比；挑选多件时可一次调用 `check_customer_items` 核对多件并取得合计金额与预算结论。客人有多样性要求（`preferences.requires_variety`）时，本次到访每种物品（按 `identifier`）只买一份，已买过的 identifier 会被原生拒收；挑货、合计和预算结论都要按 identifier 去重（`one_per_identifier_total`），价格明细里的 `varietyBuyerBonus` 只是市场加成，不是这条规则。未知自定义回调、检查或谈价仍可能改变价格，上柜台后须重新查询。符合购买偏好也不保证立即成交或完成整份特殊委托。以上三个接口只查询；是否搬上柜台仍取决于你的指令，目前不提供自动成交或选择对话选项。给客人挑货时默认忽略生产设备输入区（input）的原材料，产出区（output）可以卖；设备中正在供电或充电的电池，以及冰箱中尚未冻好或冰镇好的物品（如还没冻好的冰激凌或未冰镇饮品，物品结果 `in_use=true`）属于自用或待冻升值，`find_items` 默认不会返回，而已冻好/冰镇完成的冰箱物品可以正常出售；挑选商品时不要搬动 `in_use=true` 的物品，除非明确要求并传 `include_in_use=true`。主人用固定模式标记的物品（`pinned=true`）本身默认不作为商品出售；若被固定的是储藏容器（`STORAGE` 仓库），里面的未固定物品可以出售；若被固定的是机器（`MACHINE`），其成品区（`output`）、酒架酒槽（`wine`）或冰箱中已冻好/冰镇好的物品可以出售（原料区、模组区、电池区不出售）；若被固定的是非储藏、非机器容器（如试剂盒、净水药片盒），容器本身及里面的试纸、药片等默认都不出售，除非明确要求查看并传 `include_pinned=true`。未固定的酒架或啤酒箱既可以整件出售，也可以单卖里面的酒水。助手还能从录音机读取本次到访已经显示的对话（`get_current_customer` 的 `dialogue_history`，含客人和店主的发言），因此可以回答客人此前说过什么；它只读，不推进对话、不读取未显示的分支，也不把录音内容当成新指令。物品会返回 `stolen` 和 `heat`（0–100 的被治安检查发现概率）；给客人挑货时默认避开赃物，`find_items` 不返回它们，除非明确要求查看或挑选并传 `include_stolen=true`。

## 机械手、肋明治、等离子燃料、香烟、食品券、注射器与水质鉴定

解锁游戏内目视检查后，可以直接说“帮我鉴定这只机械手”“看看这个肋明治值不值钱”“这个等离子燃料匣怎么样”“检查柜台上的香烟有没有问题”“看看这张食品券是不是真的”或“这针管还能用吗”。助手会先查找真实物品，再调用对应的只读工具；聊天和 F7 助手指令均可使用。水质分析直接使用瓶身标签和已经测试/扫描的数据，不要求目视检查教学。

- `appraise_mechanical_hand` 返回材质、控制接口、接口标记、磨损、装甲 / 刀刃附加件、套装及原生单件鉴定基准价。价格已含套装效果，不能重复加成，也不是交易报价或鉴定服务报酬。
- `appraise_ribwich` 读取生产日期、包装厂编号、条码与厂标、肉饼 / 面包 / 酸黄瓜、包装和标志，给出外观判断、可见异常及原生单件鉴定基准价。包装已打开时按已开封价值计算；数据缺失或编号超出可见范围时返回无法判断。
- `appraise_plasma_fuel` 读取外壳颜色、裂纹、磨损、未覆盖、加固和封条，给出状态判断、可见异常及原生单件鉴定基准价。该物品没有真伪判定；状态或颜色超出已知范围时返回无法判断。
- `inspect_cigarette` 比较封条、标志、文字和包装外观，给出外观符合标准、疑似假货或无法判断，并列出异常点。仅使用检查界面可见的信息，不读取隐藏真伪；缺失数据或不支持的外观返回无法判断。
- `inspect_food_stamp` 读取防伪标、商标、芯片、文字和票面面值，给出外观判断、可见异常及 `face_value`。游戏只发行 40 / 80 / 120 / 160 / 200 / 240 信用点面值；达到 160 才应有防伪标，芯片缺失或损坏时无法兑换。仅使用检查界面可见的信息，不读取隐藏真伪。
- `inspect_injector` 读取针体、指示器、序列号、公司和型号，返回外观判断、`usable` 与可见异常。针体破损、指示器异常或召回批次的序列号会标记为不可安全使用；过期单独标记；仅标签 / 序列号 / 颜色异常标记为疑似假货。仅使用检查界面可见的信息，不读取隐藏的 `ISSUE_*` 标签或真实状态。
- `analyze_water` 分析水容器：容量、液量、灌装比例、瓶身标签等级及标签是否危险。只有试纸测试、特性暴露或水质扫描仪扫描过时才返回真实纯度与可饮用判断，成分只在扫描后返回；未测试时明确标注 `assessment_source=label`，不把标签当成真实水质。空容器返回空状态，酒类或化学容器返回不支持，不推测水质。

七项工具每次刷新当前物品，支持可访问的嵌套容器，并遵守原有锁定、主线程和场景限制。它们不提交估价、不揭露物品特性、不质问客人、不兑换食品券或完成鉴定委托；实际提交仍由玩家操作。玩法尚未解锁、物品已移走或类型不符时会返回原因。

## 液体操作

需要倒水、倒酒或清理液体容器时，可以直接说“把这瓶水倒进水壶”“把这瓶脏水倒掉”或“拿这个空瓶去水龙头接水”。助手会先查找真实容器，再调用：

- `pour_liquid`：把源容器里的液体倒入另一个液体容器，使用游戏原生的物品对物品操作，遵守所有权、锁定、容量、过滤器和温度规则。一次倒出能倒入的全部液体，不能指定毫升数；目标有过滤器时可能截留部分杂质，结果会分别给出倒出量、接收量和两边余量。空滴管对容器使用时会改为吸取液体，`direction` 会标明流向。
- `dump_liquid`：把液体倒入当铺排水口，保留容器本身。
- `fill_liquid`：在当铺水龙头接水，需要先解锁锈水或下水道水龙头；一次接满可用空间，不指定水质或毫升数。

三项工具不会凭空生成液体或容器、不会销毁物品、不改变所有权、价格或物品特性。返回 `not_poured` / `not_dumped` / `not_filled` 表示没有液体移动；水质纯度和成分仍以 `analyze_water` 的可见数据为准。

## 使用物品

助手现在可以像玩家一样对非战斗物品执行原生的“物品对物品”和“使用 / 激活”操作。例如：“用水质试纸测一下这瓶水”“给枪装上这个瞄准镜”“用医疗包处理这只动物”“用砍刀屠宰这只老鼠获取肉类”“阅读这本书”“对着这瓶水使用净水药片”。

- `use_item_on_item`：把一个真实物品拖到另一个物品或角色上，走原生 `MayTarget` / `CanTarget` / `Target`。
- `activate_item`：使用 / 激活单个物品，相当于在物品栏里双击，走原生 `MayActivateSlotItem` / `CanActivateSlotItem` / `ActivateSlotItem`。

范围与限制：

- 不再限制物品白名单；试纸、扫描仪、书籍、医疗、手术、动物、食物、机器和工具等非战斗物品都可以尝试，是否允许、消耗、打开窗口和产生效果完全由游戏原生规则决定。
- 武器可以用于屠宰动物（如老鼠）获取肉类；不会对顾客、敌人或其他角色使用武器，也不会进入射击模式或代操作霰弹枪击杀改造体顾客。武器、弹药、爆炸物和战斗能力不能用于其他目标。
- 不绕过所有权、锁定、容量或界面状态；客人物品只有在原生 `CAN_USE_ON_NON_OWNED_TAG` 允许时才能使用。试纸、扫描仪、书籍等可能打开游戏原生窗口，助手不会代替玩家点选界面；需要水质 / 物品数据时仍用 `analyze_water`、`read_document` 等只读工具。
- 不代替玩家选择对话、买卖、提交报价或改存档；交易和对话选项仍由玩家操作。结果中的 `changed=false` 表示没有观察到可见变化，不应重复执行同一次操作。

## 标签打印机与物品改名

助手可以使用真实的普通标签打印机修改道具标签，或使用蓝色标签机设置 / 清除自定义名称。例如：“把这瓶水的标签改成基础水”“把这个箱子改名为药品”“清除这个箱子的自定义名称”。先查询原生允许的标签选项，再执行编辑并核对结果；无需玩家手动选择窗口内选项。遵守原生所有权、锁定、目标和名称长度限制；改标签不会改变真实水质或品质，也不会自动交易。已有标签窗口正在使用时需先关闭。

## 阅读笔记、书籍与指南

当主人问“导师笔记里写了什么”“这本手册怎么讲”“通缉令上写了谁”时，助手会先查找真实物品，再调用只读的 `read_document`：

- 导师笔记、情报单：读取标题、正文和署名。
- 带 `BOOK_ID` 的书籍：读取书名和全部页面的小标题与正文。
- 香烟 / 食品券 / 注射器 / 机械手指南、通缉令、香烟色卡等纸面界面：读取界面中的可见文字。
- 无法阅读、文盲状态或文档类型不支持时返回具体原因，不编造内容。

`inspect_item` 的 `description` 只是物品简介，不等于文档全文；`read_document` 才是正文来源。该工具不打开窗口、不翻页、不改变物品或界面。

## 连接配置（F7）

1. 进入当铺，按 **F7**。默认服务地址为 `https://api.deepseek.com`，默认模型为 `deepseek-flash`。
2. 填写自己的 API Key。输入框以密码形式遮蔽；不要求在聊天中提供密钥。本地免密服务可留空。
3. 点击 **获取模型列表**，从下拉框选择模型，或直接填写模型 ID。获取失败、返回空列表、列表不包含当前模型时，仍可手动填写。
4. 在 **思考级别** 中选择：跟随模型默认、关闭思考、低、高、最高。低 / 高 / 最高会发送 `thinking: {"type":"enabled"}` 与 `reasoning_effort`；关闭只发送 `thinking: {"type":"disabled"}`。服务不支持这些字段时保持“跟随模型默认”。
5. 在 **聊天上下文** 中设置 **对话轮次上限（1–50）** 和 **历史 token 上限（1,000–200,000，估算）**。这两个值只决定每次发送给模型的历史；超出时从最旧的完整轮次开始省略，不会拆断工具调用与结果，也不会删除本机保存的聊天记录。只改这两个值不会清空现有聊天。
6. 在 **助手提示词** 中查看并编辑完整系统提示词，支持多行、换行和最多 16000 字。默认身份为游戏“深空当铺：可能是偷的”中的女仆助手“小鲸”，称呼用户为“主人”，语气活泼、温柔可爱，默认禁止颜文字和 emoji，除非主人明确要求；同时包含现有物品、客人和工具使用规则。**恢复默认提示词** 会填回完整默认内容；留空后保存也会使用默认值。此前原样保存的 v0.5.1 默认模板会自动更新，自定义提示词保留。
7. 点击 **保存配置**，连接、思考级别、上下文上限和提示词都会保存到本机，重启游戏后仍可读取。提示词用于之后的聊天与助手操作；保存新提示词后，下次发送会清理旧设定的聊天上下文。旧版连接配置没有提示词或上下文上限字段时，会自动采用新的默认值，保留原连接。
8. 可在 **测试对话** 中输入消息，再点击 **发送测试消息** 验证 Chat Completions 或预览人设。测试使用窗口中当前的连接、思考级别和提示词，修改后无需先保存即可预览。每次是独立测试，不会自动附带存档数据或对话历史。获取列表、测试和恢复默认都不会自动保存；关闭窗口会放弃未保存的修改。

服务地址使用 API 基础地址，支持根地址和带版本 / 代理路径的地址，如 `https://api.deepseek.com`、`https://api.openai.com/v1`、`http://127.0.0.1:1234/v1`。代码按填写的前缀追加 `/models` 和 `/chat/completions`，不会自动添加或重复 `/v1`。认证使用 `Authorization: Bearer ...`。

API Key 只用于用户填写的服务地址，不进入日志、模型列表或游戏存档。勾选 **记住 API Key** 时，密钥以明文保存在本机的连接配置文件；取消勾选后保存，会从文件中移除密钥，仅在本次运行内保留。不要分享这个文件。连接配置独立于 Mod 安装目录，更新 Mod 不覆盖它：

```text
%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\ModData\probably_ai\connection.local.json
```

打开窗口、保存配置均不会发送网络请求；“获取模型列表”“发送测试消息”、聊天发送及“执行助手指令”会联网。每条聊天消息及助手指令会附带新读取的当前客人与柜台实况；模型另外调用工具时，相应物品、容器或客人信息也会发给配置的服务。自动观察不写入聊天历史或可见记录。请求超时为 60 秒，支持取消；关闭窗口、离店或切换场景时也会取消。当前未实现自动买卖。

## 助手的“手”：物品与容器

按 **F7 → 物品与容器 / 助手操作**。

- **手动操作**：刷新 → 选来源范围 → 选具体物品 → 选目标容器 / 机器分区 → 填数量 → 预检或移动。可勾选“包含子容器中的物品”，直接选择深层文件。数量 `0` 只表示所选这一堆全部。刷新后会清除物品选择，防止误操作到下一件同名物品。
- **助手指令**：使用已保存的连接配置，输入自然语言指令后点击执行。模型必须支持 Chat Completions 的 function / tool calling。助手先查询物品，再调用操作接口，结果写入下方记录。每次指令独立处理。
- 示例：“把窗口里的普通矿石拿到柜台”“把物品栏里的文件放进档案架”“把档案架里导师笔记中的某份笔记拿到柜台”“把物品栏里的废金属放进熔炉原料区”。物品和容器名称以当前存档实际内容为准。

根容器：`inventory` = 物品栏 / 主储藏区；`counter` = 交易柜台；`customer` = 窗口 / 客人储存区；`documents` = 档案架；`trash` = 垃圾桶；`showcase` = 展示柜；`hidden` = 隐藏储藏区。储藏箱、背包、文件夹等物品的内部库存自动递归加入；熔炉等机器分别暴露 `input`、`output`、`power`、`module`、`note`，多页储藏箱分别暴露每个分页。已锁定容器只显示锁定状态，不读取内部物品。

所有嵌套对象均返回独立的会话 ID、父级和完整可读路径，例如“档案架 → 导师笔记 → 关于食品的笔记”。同名物品不会合并；物品移动后仍按实际引用识别，拆堆 / 合堆或切换存档后必须重新查询 ID。关闭容器窗口不影响查询正常可访问的内部存储。

操作使用游戏原生 `MayRemove`、槽位搜索及 `SlotMarker.TryAcceptOnce`，不改所有权、材料规则、锁定或机器工作状态。目标不接受、放不下或源位置变化都会返回具体原因。机器存在多个分区时，必须选择具体分区；投料不会主动启动机器，但游戏自身可能按其正常逻辑加工材料。移动到垃圾桶只执行投放，不调用销毁或清空垃圾桶。

停止 / 关闭窗口只取消后续动作，已经完成的移动保留。记录会显示实际 `moved` / `remaining`，部分成功不等于全部成功。每条助手指令最多 16 轮 / 48 个工具调用，按顺序执行；物品访问始终在 Unity 主线程，并在每次工具调用前刷新当前状态。

接口定义与可直接调用的 JSON 示例见 [docs/hands-api.md](docs/hands-api.md)。当前版本的游戏内布局和真实存档行为仍需要玩家实测；自动测试使用模拟游戏状态，不修改真实存档。

## 构建与安装

需要 .NET SDK 及游戏自身 Managed 目录中的 DLL，无需 Unity 编辑器、BepInEx 或 MelonLoader。

```powershell
# 在项目根目录执行，生成 dist\ProbablyAI
.\scripts\Build.ps1

# 关闭游戏后，编译并安装到游戏 Mods\ProbablyAI
.\scripts\Build.ps1 -Install

# 游戏安装在其他目录时
.\scripts\Build.ps1 -GameDirectory 'D:\SteamLibrary\steamapps\common\Probably Stolen' -Install
```

启动游戏 → Mods → 选择“深空AI：可能是DeepSeek” → 激活 → 重启游戏 → 载入当铺。关闭游戏后重新安装更新。停用请在 Mods 中取消激活并重启。

从 0.1.x 更新到 0.2.0 时，因为新增 `network` 能力，游戏可能暂不加载此 Mod。请在 Mods 中选择 **重新审核并启用 / Review and enable**，确认联网能力后重启。无需修改开发者模式或信任记录。
